CodeGraph · 本地代码知识图谱

为 Claude Code/Cursor/Codex/OpenCode 预建本地代码知识图谱，Explore agent 一次 MCP 调用即返回符号关系与源码片段，工具调用减少 94%、探索提速 77%。

1. 结论摘要

推荐基线

在中大型代码库中使用 Claude Code/Cursor 等 AI agent 做架构探索、调用链追踪、影响分析时最划算，可显著降低 token 与轮次。

补充场景 / 替代

小项目或单文件改动直接用 grep/Read 即可，不必引入；首次索引超大仓库（如 Swift 编译器 25k 文件）需等待，跨仓库语义检索仍建议配合向量检索方案。

2. 核心能力

Smart Context

一次调用返回入口点、相关符号与源码片段，省去多轮 Explore

全文检索

基于 SQLite FTS5 的符号名瞬时搜索

影响分析

追踪 callers/callees 与符号修改的影响半径

实时增量

FSEvents/inotify 监听文件变更，防抖自动同步图谱

框架路由识别

识别 Django/Flask/FastAPI/Express 等 13 个框架的路由到 handler 绑定

3. 应用场景

架构探索

回答 'X 系统如何工作' 等跨文件问题，0 file reads

重构前评估

修改前用 impact 查看符号波及范围

跨语言调用追踪

在 Python+Rust、Swift+C++ 混合仓库中追溯调用链

Agent token 优化

为 Explore subagent 提供预索引上下文，减少 90%+ 工具调用

4. 风险与缓解

主会话误用导致 context 爆炸

codegraph_explore/context 返回大段源码，须在 subagent 中调用；官方文档已写明 Claude Code 主会话禁止直接调用

首次索引耗时与磁盘开销

大型仓库需数分钟构建 .codegraph/ SQLite，CI 环境需缓存或预热

图谱与代码漂移

虽有 watcher 自动同步，但 rebase/批量改名时仍可能短暂失真，关键操作前建议 codegraph_status 验证
