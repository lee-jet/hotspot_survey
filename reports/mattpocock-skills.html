Composable Engineering Skills

Matt Pocock Skills 调研报告

mattpocock/skills 是一组面向真实工程工作的 Agent skills，强调小而可组合、可改造、可控，不追求“大流程接管”。核心思想是用工程基本功修复 Agent 常见失败：需求未对齐、语言不统一、反馈环不足、架构退化。

14 promoted skills MIT Composable Claude/Codex agents

1. 结论摘要

适合场景

适合已经用 Claude Code、Codex 或类似 coding agent 的工程团队，把“问清需求、建立领域语言、TDD、诊断、架构改善、拆 issue、交接”变成可复用技能。

使用边界

这不是一套自治 agent loop，也不是项目管理框架。它更像工程实践工具箱，需要人类持续参与和判断，尤其是 grilling、ADR、架构建议和 triage。

3. 技能体系

需求对齐

/grill-me 和 /grill-with-docs 通过逐问逐答把模糊需求压实；后者会结合 CONTEXT.md 和 ADR。

领域语言

CONTEXT.md 用来定义项目术语，减少 Agent 啰嗦和误解，让变量、文件和讨论使用一致语言。

反馈环

/tdd 强调一测一实现的 red-green-refactor；/diagnose 要先构建可重复的 pass/fail loop。

架构维护

/improve-codebase-architecture 寻找 shallow module 和 deepening opportunities，目标是 locality、leverage、testability。

工作拆解

/to-prd、/to-issues、/triage 把计划变成 issue tracker 中可执行、可分配、可验收的工作。

交接与压缩

/handoff 把当前会话压缩成交接文档；/caveman 以极简表达降低 token 使用。

4. 推荐落地方式

1. 安装npx skills@latest add mattpocock/skills。
2. 初始化运行 /setup-matt-pocock-skills，选择 issue tracker、triage labels 和 docs 路径。
3. 对齐每个复杂需求先用 /grill-with-docs 或 /grill-me。
4. 实施开发时用 /tdd、bug 用 /diagnose。
5. 维护定期用 /improve-codebase-architecture 和 /handoff。

5. 风险分析

流程依赖人类质量

这些技能故意小而可组合，意味着它们不会替你做完整项目治理。用户需要能回答问题、确认设计、审查 ADR 和判断架构建议。

文档会变成事实源

CONTEXT.md 和 ADR 会影响后续 Agent 语言和决策。错误术语或过期决策会被不断复用，需定期清理。

技能安装供应链

npx skills@latest 和 GitHub repo 直接安装都属于供应链入口。团队环境应固定版本或 commit，并走 PR 审查。

钩子和防护误配置

例如 git-guardrails-claude-code 会修改 Claude hooks。如果覆盖现有 settings 或脚本路径错误，可能造成防护失效或工作流中断。

建议控制

控制项建议
安装固定 commit，审查 SKILL.md 和插件清单，不在敏感环境直接使用 @latest。
文档CONTEXT.md 只放领域术语，不放实现细节、临时计划和秘密。
测试使用 /tdd 时坚持行为测试和公共接口，不用测试锁死实现。
架构/improve-codebase-architecture 的输出当候选建议，需要人类选择和分阶段落地。
